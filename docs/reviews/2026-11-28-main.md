## Summary
Adds debounced localStorage persistence of the editor code, hides stale trace content while a Run error is shown, titles edited code "My code" in three languages, and renames CodeVision to LiveCode with a one-time `codevision.*` to `livecode.*` storage migration. The migration is correct (collects keys first, never overwrites, only removes after a successful copy, wrapped in try/catch) and well tested. No blockers or majors; a few minor behavior edges around restore and layout.

## Minor
### 🟡 Grow-only heights are lost when the trace remounts after an error, `src/features/playground/ExecutionPanel.tsx:163`
**Problem**: The trace box, canvas and details wrappers are now unmounted while `runError` is set. `useGrowOnlyHeight` only re-measures when `example` or `stepKey` changes, so when the error clears without either changing (e.g. Reset back to the same trace), the freshly mounted elements have no min-height until the next step.
**Why it matters**: Brings back the layout jump the hook exists to prevent; cosmetic, brief.
**Suggested fix**: Include `showTrace` (or `runError`) in the hooks' dependencies, or hide the trace with CSS (`hidden`) instead of unmounting so refs and min-heights persist. Also check that the empty space under the error box looks right when the panel is maximized.

### 🟡 Reload mid-problem restores the problem's code but not the problem, `src/store/playgroundStore.ts:162`
**Problem**: Only `code` is persisted; `problemId`/`exampleId` always reset to the first example. After a reload while on a problem, the editor holds the problem's starter or edited code, titled "My code", with the first example's trace beside it and no Check panel.
**Why it matters**: Consistent with "restore code only", but the student can lose their way back to the Check flow, and the Execution panel shows an unrelated example. Worth a conscious product decision.
**Suggested fix**: Accept and document it, or also persist `problemId`/`exampleId` (validated against the data on load) so the restore is coherent.

### 🟡 Only `pagehide` flushes a pending save, `src/store/playgroundStore.ts:367`
**Problem**: On mobile browsers a backgrounded tab may be killed without `pagehide`; `visibilitychange` (hidden) is the more reliable signal. Two tabs also overwrite each other (last writer wins).
**Why it matters**: Up to 500 ms of typing can be lost on mobile; low impact.
**Suggested fix**: Also flush on `visibilitychange` when `document.visibilityState === 'hidden'`.

## Strengths
- `migrateStorage` is minimal and safe: collects keys before mutating, copies only when the new key is absent, and an exception in `setItem` aborts before the old key is removed. `index.html` falls back to the old theme key so there is no flash on the first load.
- Persistence is debounced, flushed on `pagehide`, guarded by try/catch and `typeof window`, and the tests cover restore, debounce timing, flush, key prefix and throwing storage using module re-imports.
- All three languages updated consistently, including the docs and changelog.
